# 材质管线与灯光响应补充文档 (Material Pipeline & Light Response)

> 本文是 `SKILL.md` 的补充：补充「主节点 ↔ 光源拓展BSDF」的分工定位、正确串联姿势，以及 EEVEE 实机踩坑修复记录。配套场景：室内楼梯间照片还原（写实照片 → 插件 NPR 材质管线还原）。

## 1. 核心分工（作者补充信息，务必先理解再动手）

本插件的两类节点组**职责不同，不可互相替代**：

| 节点组 | 对什么反应 | 干什么 | 典型用法 |
|---|---|---|---|
| **主节点** | **灯光（Shader to RGB 提取亮度）** | 二分/平滑明暗、亮部/暗部**染色**、亮暗明度控制 | 材质的**明暗骨架**：决定受光面/背光面颜色与明度，是散装管线第一级 |
| **光源拓展BSDF**（原理化/金属/光泽/漫射拓展光源） | **Lightgroup ID**（灯光组） | 把**指定灯光组**照亮的颜色提取出来，按 Blending Mode 混合到材质 | 多光源分层染色：主光暖/补光冷、某盏灯只影响某区域/某材质 |

一句话：**主节点管"灯光怎么照亮材质"（全局明暗），光源拓展组管"哪盏灯给材质染什么色"（灯光分层）**。

### 推荐管线

```
主节点(明暗+亮暗染色) → [光源拓展组(多光源染色,按需)] → 脏迹/AO/高光/反射(质感) → 渐变(空间渐变,可选) → 输出
```

- 写实还原：主节点 `亮部范围=1.0 暗部范围=0.0` + `Smoother Step` 过渡 ≈ 柔和漫反射；需要硬二分则 `Stepped Linear` + 小 `阶梯步数`。
- 灯光分层：View Layer Properties → Light Groups 建组，`light.data.lightgroup_id` 分配，光源拓展组 `Lightgroup ID` 指定响应组（`-1` = 全部灯光）。
- 场景**没有配置灯光组**时，光源拓展组务必设 `Lightgroup ID = -1`，否则该组完全不响应（只响应 0 号组）。

## 2. 主节点正确用法（对灯光反应）

- **内部结构**：Diffuse BSDF → Shader to RGB → 提取灯光亮度 → 亮部染色组/暗部染色组 → HSV → Mix（Factor=光照系数）。**Diffuse BSDF 的 Color 未连接（默认 0.8 灰），它只用于算光照系数，不影响颜色**。颜色由 `Color` 输入 → 亮/暗部染色决定。
- **亮/暗部染色是上色的主通道**：`亮部`/`暗部` 颜色 + `亮部染色强度`/`暗部染色强度`。要"光影颜色"（如暖光冷影），直接调这两个染色，不要依赖漫射组 Color。
- **亮/暗部明度**：`亮部明度`/`暗部明度` 控制受光/背光明度倍率。EEVEE 下主节点输出可能偏亮，需配合压低（实测 0.4~0.75 区间常用）。
- **二分 vs 平滑**：`过渡方式` = `Stepped Linear`(硬二分) / `Smoother Step`(平滑)；`亮部范围`/`暗部范围` 定阈值。

### 实操验证（照片还原任务实测）
- 主节点**单独接输出**时能正确输出受光照亮的颜色（亮度≈214，照片目标≈100 亮区）——说明主节点本身是"对灯光反应"的正确节点。
- ⚠️ **不要把漫射拓展光源接在主节点之后当"提亮器"**：漫射拓展光源内部 Diffuse BSDF 用默认 0.8 灰算灯光色，Multiply 后会**显著压暗**主节点结果（实测 214 → 44），且该压暗**不随漫射 Color 提升而恢复**。如果串联后材质过暗，优先检查是否夹了漫射拓展光源。

### 使用模型贴图时（作者补充）
- **把贴图连接到主节点的 `Color` 上**，然后**关闭 `亮部染色强度` 和 `暗部染色强度`**（设为 0）——此时材质直接呈现贴图本身，主节点只负责明暗二分/平滑与灯光反应，不做额外染色。
- **其他节点做法类似**：接贴图时先把该节点的染色/上色类参数关闭（强度归 0），让贴图原色直接通过。
- **当用户需要时**，再把例如 `亮部染色`、`暗部染色` 的**强度值拉起来**，在贴图基础上叠加光影染色效果。

## 3. 光源拓展BSDF 正确用法（对 Lightgroup 反应）

- 内部结构：Diffuse/Glossy/Metal/Principled BSDF → Shader to RGB → 蓝通道 Map Range 得亮度系数 → HSV/HSL 处理 → 与 `Color` 按 `Blending Mode` 混合 → `Result`。
- 公共输出：`Result`(颜色)、`灯光颜色系数`(颜色)、`灯光亮度系数`(浮点，可做其他组的 Factor)。
- **Blending Mode 语义**（实测）：
  - `Multiply` = 灯光色 × Color，会**压暗**（适合暗部叠加，但注意它把 Color 也乘进去）。
  - `Mix` 在 Factor 未连接（默认 1.0）时 ≈ 全取 B（灯光色），Color 基本不参与。
  - `Add` 提亮（易过曝，慎用）。
- **EEVEE 限制**：Shader to RGB 只含**直接光照**，不含环境光/世界背景光 → 暗部会纯黑。若需要 HDR 背景可见但不想给模型打光，用"双 Background + Mix Shader + Is Camera Ray"（见 §4.5）；若确实需要环境光补亮，可提高世界背景强度或加无阴影环境灯（Area，能量按 EEVEE 瓦特计需较大，如 300~500W 才可见）。
- 多光源染色流程：
  1. View Layer → Light Groups 建组（KeyLight=0、FillLight=1…）
  2. 灯 `light.data.lightgroup_id = 0/1`
  3. 材质串联 `主节点 → 漫射拓展光源(Lightgroup=0,暖) → 光泽拓展光源(Lightgroup=1,冷) → 输出`
  4. 用 `灯光亮度系数` 输出接其他组 Factor，做"某灯只影响某区域"的遮罩。

## 4. 渐变组实操（控制器驱动，EEVEE 踩坑）

- 一键添加：`bpy.ops.node.add_gradient_group()` → 自动创建 `{物体名}_控制器` 空物体并**自动串联**（原 Surface → 组.基础色，组.Color → 输出）。
- ⚠️ **控制器必须关联**：渐变组内部 `Texture Coordinate.002` 的 `object` 属性必须指向控制器空物体。若为 `None`，渐变值恒定 0 → 完全看不到渐变。重建时 `add_gradient_group` 会自动关联；手动建组后要 `tc.object = bpy.data.objects['{物体名}_控制器']`。
- ⚠️ **Menu[1] 决定坐标来源**：`Texture Coordinate`（物体自身坐标）vs `空物体坐标`（控制器坐标）。选"空物体坐标"且控制器未关联 = 恒 0；选"Texture Coordinate"走物体坐标（薄板物体沿薄轴无跨度，渐变看不出）。
- ⚠️ **组实例的 Rotation/Location/缩放 可能因接口映射错位而不生效**（改了渲染无变化）。诊断：检查内部 `Mapping.001` 的实际 Rotation 值、`Menu Switch.001` 的 select。若内部与实例不一致，**直接改内部 Mapping 节点**或重建渐变组。
- **验证技巧（看不到效果时）**：先改变摄像机位置/角度渲染验证渐变是否有效（把相机挪到能看清渐变方向的位置），确认有效后，再回到用户指定的摄像机位置/角度，根据需求调节参数。不要因为"当前机位看不出"就误判渐变失效。
- **Texture Coordinate 绑定语义**（作者补充）：
  - **不绑定物体**（`Texture Coordinate.002.object = None` 且走物体坐标）：渐变效果 = **这个模型的物体坐标**。
  - **绑定圆形空物体**（`Texture Coordinate.002.object = 空物体`，走空物体坐标）：渐变效果 = **空物体的坐标**。
  - **空物体缩放**（`ctrl.scale`）：控制渐变的**缓急程度/范围**——拉长对应轴，渐变过渡更缓慢、跨度更大；缩小则更急促。
- **方向控制**：渐变 Linear 默认沿 X 轴。要沿世界 Y（常见：靠近镜头黑），给控制器空物体旋转，使局部 X 轴对准世界 Y（如 `rotation_euler = (0, 0, -1.571)` 绕 Z 转 -90°）。
- **缓慢度**：拉长**控制器空物体的 scale**（对应渐变方向的那个局部轴，注意旋转后局部轴≠世界轴：绕 Z 转 -90° 时局部 X = 世界 Y，所以要拉长 `ctrl.scale.x`）。渐变组内部 Mapping 的 Scale 也可调，但以控制器 scale 为准。
- **反转**：用组内 `Menu Switch`（"不反转 / Invert Color"），对应组实例的 Menu 端口，设 `'Invert Color'`。
- 位置微调：控制器空物体沿世界 Y 移动，可把过渡区（明→暗分界）搬到目标位置；"往世界坐标 y 轴方向走一点" = `ctrl.location.y` 增大。

## 4.5 世界环境（Background）正确做法 —— "看得见 HDR 但不对模型打光"（作者补充）

> 作者制作场景渲染的习惯做法，用于解决"EEVEE 暗部全黑"时"既想要 HDR 环境背景、又不想 HDR 给模型材质加亮度"的矛盾。

- **做法**：两个 Background 节点 → Mix Shader 混合 → World Output。
  - **Background A：值设为 0**（颜色 0 / 强度 0）—— 这个"0 背景"是**不影响场景材质亮度**的关键。
  - **Background B：HDR 贴图或任意环境内容** —— 提供可见的世界环境（背景画面）。
  - **Mix Shader 的 Factor**：用光程节点的 **【是摄像机射线】(Is Camera Ray)** 输出。
- **效果**：摄像机射线看到的 = Background B（HDR 背景可见）；非摄像机射线（打到模型上的光）走的 = Background A（0，不贡献亮度）→ **模型材质不受 HDR 环境光影响，暗部保持纯黑**（由真实灯光决定）。
- **如果效果失效**：**交换 Mix Shader 的两个插槽**（A/B 对调）即可。
- 节点示意：
  ```
  Background A(0) ──┐
                    ├─ Mix Shader ─→ World Output.Surface
  Background B(HDR) ─┤   Factor ← Light Path.Is Camera Ray
  ```

## 5. 还原类任务通用工作流（本次楼梯间照片还原沉淀）

1. **分析参考图**：按物体投影到参考图像素，采样目标色（含"黄差" R-B、G-B 判断色偏）。
2. **搭明暗骨架**：主节点（亮部/暗部范围、过渡方式、明暗度、亮暗染色）。
3. **质感细节**：脏迹(做旧/颗粒)、AO(缝隙)、高光(金属)、反射(镜面)。
4. **空间渐变**：渐变组（如楼梯墙"靠近镜头黑"）。
5. **环境光**：EEVEE 下先确认暗部不全黑（世界背景/环境灯）。
6. **逐项校准**：渲染 → 像素采样对比 → 微调（色偏/明暗/纹理强度）。

### 本次任务几个"参数影响不生效"的根因速查
| 现象 | 根因 | 修复 |
|---|---|---|
| 改了漫射 Color 亮度不变 | 漫射拓展光源 Multiply 灯光色，灯光色受光照上限 | 别指望漫射提亮；改主节点明暗度，或去掉漫射组 |
| 渐变完全看不到 | Texture Coordinate.002.object = None | 关联控制器空物体 |
| 渐变方向不对/改了没反应 | 组实例 Rotation 未传入内部 Mapping / Menu 选了空物体坐标但未关联 | 直接改内部 Mapping 或重建；确认 Menu[1] |
| 暗部全黑 | EEVEE Shader to RGB 不含环境光 | 用"双 Background + Mix Shader + Is Camera Ray"（见 §4.5）让 HDR 背景可见但不给模型打光；暗部亮度靠真实灯光/主节点明暗度控制 |
| 高光/反射过曝一片白 | EEVEE_SPECULAR Shader to RGB 输出 HDR | 高光开关降到 0.05~0.1 |
